# 效能調整與狀態紀錄

本機監測維持每秒檢查通知資料是否變動；未變動時不建立 SQLite 快照或重複處理訊息。資料庫或 WAL 大小、時間戳、檔頭／尾摘要變動時會重新掃描。即使摘要未變，每 30 秒仍強制完整補掃目前的回溯時段；啟動與讀取失敗後也會重新掃描。健康狀態仍以真正成功查詢時間判斷，不把「跳過查詢」當成成功收訊。

已完成工作使用最多 2,048 筆的輕量狀態快取，只保存狀態與到期時間，不保存聊天、金鑰或收據內容。資料修改即失效，最長 30 秒強制重讀。尚未到期的重試不做多餘解密；需要執行時仍讀取正式檔案。重啟會清除快取，從加密紀錄恢復，不刪除已完成歷史或未完成通知。

搬遷／停止旗標的重複讀取合併為最多每 250 毫秒一次；解析失敗仍停止接收新工作。這項短快取不改變等待進行中 HTTP 操作完成的安全停止流程。

每個程序每 30 秒記錄自己的 CPU、記憶體、執行緒、控制代碼數、實際查詢／跳過次數與快取命中次數。CPU 是全機邏輯處理器標準化後的平均百分比，第一筆尚無比較基準。效能紀錄為 `logs/performance-日期-角色.jsonl`，保留最近 7 個日曆日，自動清除這項功能自己的過期效能紀錄，不清除其他日誌。

重新開啟本機儀表板，可在五個程序卡片查看目前 CPU 與記憶體。若需近 24 小時最低／最高記憶體與 CPU 摘要，從 Windows PowerShell 執行同資料夾的 `Get-PerformanceReport.ps1`。有獨立資料目錄時，使用 `-ConfigPath` 指向該資料目錄的 appsettings.json；可加 `-Hours 48` 查近 48 小時，最多 168 小時。

效能檔不含聊天、群組、人員、API 金鑰或 receipt。資料庫探測摘要只放記憶體、不寫入效能檔。效能紀錄不跟隨加密搬遷；新機會重新建立。

這些調整減少重複工作，但不保證解決所有卡頓。需在實際發生卡頓時，比較效能紀錄與 Windows 工作管理員；不得將短時間取樣視為排除長期記憶體成長的證據。舊的 0.2.0 ZIP 不會自動更新；本次部署針對目前本機監測核心，後續重新打包會帶入此功能。
