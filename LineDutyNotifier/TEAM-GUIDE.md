# 班表與多人通知

## 目前模式：不使用班表

### 多人測試模式

### 緊急測試按鈕

在人員表選取已儲存的人員，按「傳送緊急測試（2 分鐘）」並核對姓名後確認。只送給該人，未勾選啟用的人員也可測試。測試為等級 2、每 30 秒重複、最長 120 秒；正式通知的 1 小時設定不變。每人同時最多一筆進行中的測試；測試獨立於接刀排程，不觸發正式排程或管理者未確認追蹤。

可在手機按 Acknowledge，或選取同一人按「停止此人的緊急測試」。未送出的工作立即取消；已送出者透過 receipt 要求停止，斷線會重試，介面顯示「停止中」而不是假稱已停止。若發送回應遺失而拿不到 receipt，仍可能已送達，請在手機確認或等待最多 2 分鐘自然到期。按「重新整理」後看個別通知紀錄，可辨認測試、已接受、本人確認、到期與取消狀態。

背景監測器必須運作才能發送／追蹤／遠端停止。待送測試超過建立後 5 分鐘不再重送，避免隔天重啟突然響鈴。測試按鈕只排入佇列，不保證手機收到；請事先與同事約好時間。

正式設定使用 `NotificationRouting.Mode: AllEnabled`：通知所有勾選「啟用」的人員，不讀取班表，也不需要勾選全時段當班。每人依自己的提前量安排緊急通知，使用獨立 receipt；一人確認不會停止其他人的提醒。逾時恢復仍只通知管理者核對，五分鐘未確認的追蹤也只送管理者。

從「接刀排程與人員」新增同事，填姓名、個人 Pushover user key 與提前分鐘，勾選啟用並儲存。可先取消啟用、儲存後按「傳送一般測試通知」，確認手機收到再啟用。啟用會加入新排程和仍進行中的排程，已完成的排程不重播；停用會撤下其未完成提醒。班表匯入、辨識、發布仍停用。

目前僅啟用功能，須實際新增同事後才能做多人手機確認測試。API app token 沿用主機設定，不需每人另填。

`NotificationRouting.Mode` 預設為 `OwnerOnly`：所有自動接刀通知直接送給固定識別碼 `owner` 的原收件人，不查班表、不加入其他當班人員，也不依全時段開關改變收件人。原有人員與班表資料保留，班表匯入入口隱藏，匯入／AI 辨識／發布功能停用。

從儀表板「接刀排程與人員」仍可查看、補時間、改期或取消接刀排程，並調整提前量。精確未來時間仍先一般提醒，預設提前 60 分鐘緊急提醒；直接出勤立即緊急提醒；已確認但時間模糊則立即緊急提醒並標示「已確認接刀需求，時間待補」。缺班表不再顯示時間需核對。

升級會更新尚未嘗試發送的待發通知文字，不重播已送出的通知，不改變既有 receipt。以下多人班表說明僅供日後重新啟用 `Roster` 模式時參考。

從本機儀表板右上角「班表與人員」開啟管理畫面。第一版使用集中式 Windows 監測及 Pushover，所有資料由執行監測器的 Windows 帳號加密保存。

## 你的預設設定

既有收件人以固定識別碼 `owner` 登錄為「我（管理者）」，啟用管理者與全時段當班，提前量 60 分鐘。全時段涵蓋沒有班表的日期、夜間及假日。管理者／當班／備援名單以人員識別碼合併，同一提醒階段不重複發送。

全時段當班不改變提醒時機：精確的未來接刀排程先一般提醒，到各人設定的提前時間才緊急提醒；直接出勤或已確認但鐘點不明時立即緊急提醒。可在人員管理修改提前量或關閉全時段當班。

## 加入同事

1. 按「新增人員」，填入姓名、班表別名、Pushover user key 及提前分鐘。
2. 收件資料以遮蔽欄位輸入，儲存後加密。修改既有人員時，留空表示保留原值。
3. 按「傳送一般測試通知」，由同事回報是否收到。服務接受不等於手機已響鈴。
4. 班表發布後，該時段的所有當班人員都加入分派。停用人員會撤下其待發通知；不能停用最後一位管理者。

## 圖片／PDF 班表

1. 選擇 PNG、JPEG 或 PDF，檔案上限 15 MB。原檔加密保存在草稿內。
2. 按「AI 辨識為草稿」會將所選班表送到既有 AI API；使用量納入 token 統計。辨識在背景執行，失敗保留草稿。
3. 左側可看原圖，PDF 支援逐頁預覽；右側可逐列修改姓名、日期、班別及起訖時間。
4. 沒有明確起訖時間時，輸入班別代碼及時間，按「套用班別時間」。結束不晚於開始表示跨至隔日，仍需核對。
5. 填寫涵蓋日期，逐列確認後「確認並發布」。未發布草稿不影響通知。發布會取代涵蓋日期內開始的班次；保留前一天開始的跨日班次。

缺少年月、姓名無法唯一對應、時間空白、起訖錯誤或超過 48 小時的單一班次會阻止發布。載入已發布班表編輯時會建立新草稿，保留原版。沒有班次的期間會進入備援提醒，不視為系統已停用。

## 排程、異動與確認

- 精確日期／時間使用台灣時區；班次包含開始、不包含結束。相對日期參照原訊息日期。只有「三點」且上午／下午不明等情況保持待確認，不臆測。
- 無法分派時通知當次收到事件時可辨識的當班人員與管理者；已確認需求使用緊急提醒，疑似需求使用一般提醒。
- 一人一份推播與 receipt，一人的確認不停止另一人的響鈴。一般告知不取代接刀前的緊急提醒。
- 緊急提醒接受後 5 分鐘仍未確認，管理者收到一次一般追蹤提醒。Pushover 重複次數及時限仍依服務限制與原設定，不保證無限響鈴。
- 換班後重算待發對象，新接班者收到相應提醒，原人員收到異動告知。離開後再接回同一排程會建立新的分派紀錄，不抹除舊通知歷史。
- 自動改期／取消只處理「有明確原日期時間，且同群組只有一個吻合的活動排程」；改期還必須有明確新時間。含疑問或否定取消的語句不自動取消。
- 無法對應的異動列為「異動待核對」。選取後可看本機原訊息，再於下拉選單選擇原排程，確認修改時間或取消。相同時刻多台刀需人工選擇。
- 「試跑選取排程」只顯示對象、時間及原因，不建立通知。
- 已完成的直接出勤事件不跟隨日後班次重新提醒。已過接刀時間的補收事件／尚未成功送出的恢復工作先交管理者核對。

管理畫面的原訊息僅在本機選取排程時顯示；新多人推播只含接刀時間、排程識別碼及核對提示，不轉送原始聊天或病人內容。

## 手機通知標示

通知依用途區分，不以收件人是否為管理員判斷：

- `【出勤通知】緊急接刀提醒`：本人接刀／出勤提醒；確認只停止自己的這則緊急提醒。
- `【出勤通知】接刀排程預告`：提前告知，後續緊急提醒仍保留。
- `【出勤通知】疑似需求待確認`：查看群組，尚非確認出勤指令。
- `【出勤通知】排程異動`：提醒受影響人員核對最新安排。
- `【管理員通知】出勤人員尚未確認`：請追蹤尚未確認的人員，不是新增出勤指令。
- `【管理員通知】過時排程待核對`：請先確認延遲收到的排程是否有效。
- 測試一律標為 `【測試】`，並註明「非出勤」。

管理員收到自己的出勤提醒仍顯示「出勤通知」。每則內文開頭附用途及處理方式；標示不改變收件人、優先等級、30 秒重試或原有到期時間。已接受的通知不因標示更新而重送；只有後續送出的通知會使用新標示。多人模式下的疑似需求仍依現有分派規則通知，並未改成只傳給管理員。

## 執行與相容性

五個背景角色為 Collector、Classifier、Scheduler、Sender、Receipts。Collector 保持既有輪詢；Scheduler 約每 5 秒核對持久化請求、班表及到時工作，心跳約 30 秒。管理畫面的重新整理按鈕讀取最新明細；主儀表板仍自動更新。

新增資料都在被 Git 忽略的 `state`：`team` 保存人員、發布班表及版本歷史，`rosters` 保存加密草稿／原圖，`dispatch` 保存待分派請求，`schedules` 保存接刀排程；`outbox` 加入收件人、排程版本、提醒階段及分派次序。檔案原子更新，跨程序修改使用同一把鎖。

升級初始化一次性保留既有 inbox 識別碼與原收件資料；舊工作仍走原流程，舊紀錄不重播。集中電腦仍需維持 LINE 與 Windows 通知運作；本功能不新增開機登入或防睡眠設定。

隔離測試指令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\LineDutyNotifier\Test-Team.ps1 -Ui
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File .\LineDutyNotifier\Test-Roster.ps1
```

`Test-Roster.ps1 -LiveAi` 另用合成 PDF 呼叫一次真實 AI，會消耗少量額度；測試不使用真實班表。新增同事後仍需完成該手機的實際收件測試，才能核對端到端效果。

實作依據：[OpenAI 官方檔案輸入](https://developers.openai.com/api/docs/guides/file-inputs) 的 PDF／圖片輸入與結構化草稿；[Pushover API](https://pushover.net/api) 的逐人緊急提醒、receipt 查詢及取消。免費通知管道尚未實作。
